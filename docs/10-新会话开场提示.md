# 10 新会话开场提示（直接复制粘贴）

> 上下文用尽 / 换工具 / 换人接手时，把下面 **「开场白」** 整段粘给新的 AI 会话即可，不需要复述历史。

## 1. 开场白（复制这一段就够）

```
你在接手一个已在开发中的毕业设计项目：校园二手教材循环平台「同窗书」。
仓库：D:\Users\86180\Desktop\second-hand_bookstore（git 主分支 main，远端已配置）。

请先按顺序读这三个文件，读完再动手，不要凭猜测回答：
1) AGENTS.md                      —— 项目宪法：技术栈、目录、命令、环境事实、设计决策、踩坑清单、协作规则
2) docs/09-项目状态与交接.md       —— 当前进度、验证基线、提交时间线、未完成清单（P0/P1/P2）
3) docs/05-开发会话与交付记录.md   —— 历史决策流水（可选，需要追溯"为什么这么做"时读）

读完后请先给我一个 10 行以内的现状汇报：已完成什么、当前验证结果、未完成清单里你建议先做哪一项，
然后再等我下指令。不要自动改代码，不要重新设计架构。

硬性约束：
- 后端改完必须 .\mvnw.cmd -q -DskipTests compile 通过；接口改动必须跑 tools\smoke.ps1 与 tools\e2e-trade.ps1
- 前端改完必须 pnpm build 通过（pwsh 下别用 npm，npm.ps1 被执行策略拦截）
- 改表流程：db/schema.sql → node tools/gen-entities.js → node tools/gen-h2-schema.js → 删仓库根 data/ → 重启
- 凭证（Spug 模板编码、JWT 密钥、数据库密码）不得写进仓库，只能放 application-*-local.yml（已 gitignore）或环境变量
- 不许说"应该能跑"，要么贴出验证输出，要么说"未验证"
```

## 2. 三种场景的追加指令

**继续写功能**

```
接着做 docs/09 第 7 节未完成清单里的 <某项>。先给方案（涉及哪些文件、怎么验证），我确认后再改。
```

**修 bug**

```
现象：<截图/报错原文>
复现：<命令或页面路径>
先定位根因再改，别猜。改完贴出验证输出。
```

**写论文素材**

```
按 docs/09 第 7 节的 P0 项产出论文素材：先出"系统测试用例表"（编号/用例/步骤/预期/实际/结论），
数据从 tools/smoke.ps1 与 tools/e2e-trade.ps1 的断言里提取，不要编造未测过的结果。
```

## 3. 交接前的 60 秒自查（每次大阶段结束时）

1. `git status --short` 是否干净（有改动就先提交，别让工作区漂着）。
2. 有没有新的"坑"或"决策理由"需要补进 `AGENTS.md` 第 7/8 节。
3. `docs/09` 的第 2/5/6/7 节是否还是最新的（交付物、验证结果、提交、待办）。
4. 需要的凭证是否已就位（真实短信才要 `application-spug-local.yml`）。

## 4. 给新会话的"红线"

- 不要重写架构、不要换技术栈、不要把 `server/` 拆成微服务。
- 不要在没有验证的情况下声称"已修复/已通过"。
- 不要把 `.vite`、`dist/`、`data/`、`node_modules/` 提交进 git。
- 涉及产品口径（小程序要不要做、支不支持支付）先问，不擅自扩展。

## 5. 万一 git 也丢了

`git bundle` 是完整的离线副本（含全部历史与分支）：

```powershell
# 备份
git bundle create ..\second-hand_bookstore.bundle --all
# 恢复
git clone second-hand_bookstore.bundle second-hand_bookstore
```

再配合 `tools/setup-dev.ps1`，任何一台 Windows 机器 5 分钟内就能跑起来。
