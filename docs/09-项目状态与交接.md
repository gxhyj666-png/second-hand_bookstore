## 8. 已知短板与答辩口径（提前准备答案）

1. **实名/人脸/ISBN 是 mock** → 答："能力与供应商解耦，`SmsProvider`/`IdentityService` 有接口层，换真实服务只改实现类；短信已经真接了 Spug 并现场演示。"
2. **小程序是旧流程** → 答："定位参考实现，主线在响应式 Web；接口完全复用，重做 UI 即可。"
3. **图片只存 URL** → 答："当前阶段接口接收 URL，对象存储接入是部署项（见 P1），不使用本地磁盘是为了无状态扩容。"
4. **没有 Redis / 消息队列** → 答："JWT 无状态、通知走库内表 + 定时拉取，当前量级不需要；引入点已在 compose 预留位置。"
5. **推荐是规则召回** → 答："同课程 + 收藏共现，冷启动兜底热门；数据量上来换 ItemCF，接口不变。"
6. **创新点是什么** → 答："课程—教材版本归一解决'第几版'歧义；三态担保 + 15 分钟核销码把线下交易线上化；协商→仲裁两级 + 信用分爽约惩戒形成闭环。"

## 9. 新环境恢复步骤（换机器 / 新会话）

1. `git clone` 或解压仓库，确认 `mvnw`、`pom.xml`、`.run/` 在根目录。
2. `powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-dev.ps1`（自动找 JDK17、下 Maven、装依赖、写 IDEA SDK 与本地配置）。
3. IDEA 打开仓库根 → 等 Maven 导入 → 运行配置选 `Backend dev (H2)`。
4. `powershell -NoProfile -ExecutionPolicy Bypass -File tools\smoke.ps1` 自检是否 17/17。
5. 需要真短信时：把 Spug 模板编码写进 `server/src/main/resources/application-spug-local.yml`，用 `tools\start-backend.ps1 -Sms spug` 启动。
