## 2. 需求是怎么长出来的

原始材料只有一页 25 页的 PPT（《21.黄一健-同窗书_校园教材循环》），4 个模块、11 个功能。对照学校《毕业设计选题注意事项》后暴露出三个问题：

| 问题 | 判断依据 | 处理 |
|---|---|---|
| 模块数不足 | 注意事项要求「系统性、工作量适中、至少 5 个模块」，PPT 只有 4 个 | 扩到 **8 个模块**，每个模块都有独立的数据表与业务规则 |
| 技术栈与学校要求不匹配 | 注意事项写明「要采用流行技术、体现技术与架构」；原 PPT 是 Node/NestJS | 改为 **Spring Boot 3 + MyBatis-Plus + MySQL 8 + Redis + 微信小程序 + Vue3** |
| 题目偏「管理系统」 | 注意事项明确「避免图书管理系统类」 | 把核心业务锁在**担保交易 + 自提核销 + 班级接龙**，管理后台只是配套 |

题目最终定为：**基于 Spring Boot 和微信小程序的校园二手教材循环平台的设计与实现**。
（备选：「基于担保交易与自提核销的校园教材循环平台」「基于课程知识图谱的校园二手教材撮合平台」）

## 3. 八个模块（答辩按这个顺序讲）

| # | 模块 | 关键能力 | 技术落点 |
|---|---|---|---|
| 0 | 用户与认证 | 注册/登录、微信登录、学号实名、角色与冻结 | JWT（HS256，7 天）、BCrypt、`role` 五值、每请求读状态实现即时封禁 |
| 1 | 课程—教材知识库 | 课程、教材、课程-教材绑定、版本与价格指数 | 多对多桥表 + 按「课程+学期+必修」聚合，`price_index` 实时算 min/max/avg |
| 2 | 商品发布与品相 | 发布、图片、品相五档、审核、下架 | 状态机 `ON_SALE/LOCKED/SOLD/OFFLINE/REJECTED`，审核拒绝留 `reject_reason` |
| 3 | 检索匹配与推荐 | 关键词、课程过滤、价格区间、排序 | SQL 条件检索（标题/作者/ISBN/课程名）+ 简单召回（收藏/成交同课程 → 兜底热门） |
| 4 | 订单与担保交易 | 下单、支付冻结、超时关单、退款 | 幂等表防重复下单、条件更新 `ON_SALE→LOCKED` 防超卖、`@Scheduled` 每分钟扫超时单 |
| 5 | 自提点与核销 | 自提点、动态核销码、店员核销、结算 | HMAC-SHA256 取 6 位码，30 秒窗口、允许上一窗口容错；核销写 `biz_pickup_verify` + `biz_settlement` |
| 6 | 信用评价与纠纷 | 双向评价、信用分、工单 | 评价驱动信用分（≥4 +3 / =3 0 / <3 -3），工单状态 OPEN/PROCESSING/RESOLVED |
| 7 | 班级接龙与运营 | 团长开团、邀请码、成团、看板 | 接龙满额置 DONE；看板含 GMV、7 日趋势、六阶段漏斗、品相分布 |
| 8 | 通知与埋点 | 站内信、行为埋点、日报表 | `msg_notice` + `biz_track_event` + `stat_daily`（唯一键 `stat_date+school_id`） |

> 为什么把「AI 推荐」降级：答辩风险高（说不出召回/排序/冷启动的实验结论），收益低。用「课程维度的规则召回」讲清楚冷启动与可解释性，比堆一个黑盒更稳。

## 4. 数据库设计的四个关键取舍

1. **24 张表全部自增主键 + `created_at/updated_at`**：教学项目不需要分布式 ID，自增让外键与索引更直观。
2. **逻辑删除 `deleted`**：配合 `@TableLogic` 全局生效；代价是唯一索引要带 `deleted` 或改用「业务唯一键 + 状态」，文档 02 里专门写了这个冲突与解法。
3. **`sys_idempotent(request_id, scene)` 独立幂等表**：下单请求先插 PROCESSING 再执行业务，失败改 FAILED，重复请求直接读既有结果——比「查订单表判断重复」更通用。
4. **担保交易用「状态 + 时间戳列」而非单独流水表**：`paid_at/verified_at/settled_at/closed_at` 四个时间点足以画出订单生命周期，减少 join。

## 5. 接口约定

- 统一响应：`{ "code": 0, "message": "ok", "data": ... }`，业务错误码 4xxxx（40000 参数、40100 未登录、40300 无权限、40400 不存在、40900 状态冲突）
- 分页：`{ "records": [], "total": 0, "page": 1, "size": 10 }`
- 路径前缀 `/v1`，鉴权头 `Authorization: Bearer <token>`
- 小程序与管理后台都走 `/api` 前缀，由 Vite dev proxy / Nginx 反代到 `/v1`（**后端本身不带 `/api`**，这是最容易配错的一处，见 §7.8）

**答辩可现场跑的 14 步主链路**（`tools/smoke.ps1`，一条命令全绿）：

```
健康检查 → 买家登录 → 店员登录 → 管理员看板 → 课程/教材 → 检索
→ 商品详情+价格指数 → 推荐 → 下单(幂等) → 支付冻结 → 标记待核销
→ 取动态核销码 → 店员核销 → 信用分到账
```

## 7. 开发过程中踩的坑（写论文「实现」章节很值钱）

| # | 现象 | 原因 | 修复 |
|---|---|---|---|
| 1 | 生成实体时 node `FATAL ERROR: Ineffective mark-compacts near heap limit` | 正则 `/CREATE TABLE([\s\S]*?)\n\)\s*ENGINE/` 在 487 行 SQL 上回溯爆炸 | 改成 `split(/CREATE TABLE\s+`?(\w+)`?/)` + `indexOf('\n)')` 截断 |
| 2 | 实体字段全是空 | schema 里列名**没有反引号**，生成器正则按 `\`col\`` 匹配 | 正则改为可选反引号，并过滤 `PRIMARY/KEY/UNIQUE/INDEX` 行 |
| 3 | `非法字符: '\ufeff'`（`OrderService.java:[1,1]`） | Windows PowerShell 5.1 的 `Set-Content -Encoding utf8` 会写 BOM | 用 `[System.IO.File]::ReadAllBytes` 判 `EF BB BF` 并去三字节；或用 `-Encoding utf8NoBOM`（pwsh 7） |
| 4 | `Constraint "uk_order" already exists` | H2 的约束名在**整个 schema 内全局唯一**，MySQL 允许每表重名 | 生成器把 `UNIQUE KEY name` 改写为 `CONSTRAINT <table>_<name> UNIQUE` |
| 5 | 种子数据插入报 `Unique index or primary key violation: sys_user_uk_openid` | `openid DEFAULT ''` + 唯一索引，5 个示例用户全是空串 | `openid` 改可空（唯一索引允许多个 NULL） |
| 6 | 接口中文全乱码 | 响应头 `Content-Type: application/json` 无 charset，Windows PowerShell 5.1 按 ISO-8859-1 解码 | `WebConfig.configureContentNegotiation` 指定 `application/json;charset=UTF-8` |
| 7 | `pnpm install` 后 esbuild 二进制没装上，构建报错 | pnpm 11 默认拦截依赖的 install 脚本 | `admin/pnpm-workspace.yaml` 写 `allowBuilds: { esbuild: true, vue-demi: true }`（`package.json` 的 `pnpm` 字段已失效） |
| 8 | 管理后台请求全 404 | 后端跑在 **8088**，而 `admin/vite.config.js` 的 proxy 与小程序的 `DEFAULT_BASE_URL` 都写着 8080 | 两处统一改 8088；Nginx 里 `/api/` 反代到 `server:8088/`（带尾斜杠去掉 `/api` 前缀） |
| 9 | Vite dev server 偶发崩溃 `EBUSY` | Windows 上编辑器原子写触发 `fs.watch` | `server.watch.usePolling = true`（interval 300） |

> 第 8 条是本次最容易被忽略的一致性 bug：dev 默认 mock 所以没人发现，一开真机联调就会全 404。

## 8. 三种运行方式

### A. 本地零依赖（最快，答辩演示首选）
```powershell
cd server
mvn spring-boot:run                    # 8088，H2 文件库，首启自动灌种子数据
# 另开一个窗口
# 另开一个窗口：用户端 Web（平台主入口）
cd web
pnpm install ; pnpm dev                # 5174，/api 代理到 8088
# 再开一个窗口：管理后台
cd admin
pnpm install ; pnpm dev                # 5173（mock 默认开）
```
小程序：微信开发者工具导入 `miniapp/`，`utils/config.js` 里 `USE_MOCK: true` 即可无后端走通。

### B. 本地完整栈（MySQL + Redis）
```powershell
docker compose up -d --build           # mysql:8 + redis:7 + server:8088 + admin:80
```

### C. 阿里云 ECS（免费试用）
见 §9；部署后访问 `http://<公网IP>/` 进管理后台，`http://<公网IP>:8088/v1/health` 验后端。

## 9. 部署到 ECS 的注意事项

- **配置建议**：2 vCPU 4 GB 经济型 e + Alibaba Cloud Linux 3 + 40 GB ESSD Entry；不用时关机，避免 300 元额度被 24 小时开着烧完（2C4G 约 ¥0.254/h，300 元只能跑约 1181 小时）。
- **安全组**只放行 22、80；**不要**放 3306/6379，MySQL/Redis 只在 compose 内网互通。
- 后端必须跑 `mysql` profile（`SPRING_PROFILES_ACTIVE=mysql`），否则会连 H2 而看不到数据。
- 内存吃紧时给 JVM 限上限：`JAVA_TOOL_OPTIONS=-Xmx512m`，并给 MySQL 加 `--innodb-buffer-pool-size=128M`。
- 公网 80 端口提供网站需要 **ICP 备案**；只用 `IP:8088` 临时演示通常不需要。
- 小程序真机联调：开发版勾「不校验合法域名」并 `setBaseUrl('http://<公网IP>:8088/api')`；正式发布才需要备案域名 + HTTPS。

## 10. 答辩预设追问

| 追问 | 一句话答法 |
|---|---|
| 为什么不用原方案的 Node/NestJS？ | 学校要求「流行技术 + 体现架构」，Spring Boot 的事务、状态机、定时任务在同一进程内可讲透，且部署单 jar 更适合毕设演示。 |
| 担保交易和普通二手交易差在哪？ | 钱先冻结在平台，核销后才结算给卖家；超时未核销自动退款，买卖双方信用分兜底。 |
| 怎么防止超卖？ | 下单用条件更新 `UPDATE ... WHERE status='ON_SALE'`，影响行数为 0 即失败，再配合幂等表防重复提交。 |
| 核销码被盗用怎么办？ | 6 位 HMAC 动态码，30 秒窗口 + 上一窗口容错，且校验「店员角色 + 订单状态」双条件。 |
| 推荐怎么做的？有算法吗？ | 显式做了「规则召回 + 可解释排序」（同课程热度、收藏/成交相似、兜底热门）；没上协同过滤是为了可控与可讲清。 |
| 数据从哪来？ | 287 份问卷（发放 470，误差约 5.8%）+ 8 本教材、6 门课的真实字段建模；种子数据按真实分布构造。 |
