# 06 · 终端形态说明（Web 优先，APK 后置）

## 背景与决策

原始毕设材料是按「微信小程序」写的。开发到三端骨架齐全后，方向调整为：

> 先把「平台」本身做出来（响应式 Web），暂不上小程序；后续可能需要移动端网页与 APK 安装包。

这不是推倒重来——后端是纯 REST + JWT，与客户端形态无关，**接口一行都没改**；变的只是用户端载体。

## 为什么选「响应式 Web + Capacitor」，而不是 uni-app

| 方案 | 现在能出什么 | 以后出 APK | 代价 |
|---|---|---|---|
| **响应式 Web + Capacitor（已采用）** | 一套页面同时适配 PC 与手机浏览器 | 加 `android/` 工程套壳，页面代码不改 | 需要 Android SDK 才能本地出包（也可用云打包） |
| uni-app 一套代码 | H5 + 后续可出小程序/APP | 云打包出 APK，不用本地 SDK | 引入 HBuilderX/uni 工具链，调试体验差，现有 Vue 代码要重写 |
| 继续原生小程序 | 小程序 | 做不了 APK | 已经验证过要 AppID + 真机 + 审核，链路长 |

关键判断：**"现在要能演示"比"以后可能要什么"权重更高**。Web 版今天就能在浏览器里跑完整链路，答辩只需要一个浏览器；APK 是"以后"，用 Capacitor 时改的是构建配置而不是业务代码，风险可控。

## 一期范围（21 个页面）

`web/src/views/` 已覆盖主链路：

首页 / 找书 / 教材详情 / 发布 / 订单（买家·卖家）/ 订单详情（支付、核销码、评价）/ 评价 /
我的 / 登录 / 注册 / 学号认证 / 个人资料 / 收藏 / 消息 / 信用记录 / 纠纷工单 /
接龙列表 / 接龙详情 / 自提点 / 课程教材 / 404。

一条「用户能自己走完」的路径：
注册 → 学号认证（待审）→ 发布教材 → 别人检索到 → 下单（选自提点）→ 支付冻结 →
卖家标记待核销 → 买家出示 6 位动态码 → 店员核销 → 结算 → 双向评价 → 信用分变化。

## 以后要 APK：三步

```powershell
cd web
pnpm add -D @capacitor/cli
pnpm add @capacitor/core @capacitor/android
npx cap init 同窗书 com.textbook.loop --web-dir=dist
npx cap add android
pnpm build ; npx cap sync android
npx cap open android      # 用 Android Studio 出包
```

**四个必须提前知道的坑**：

1. **接口地址**：APK 里没有 Nginx 反代，必须 `web/.env.production` 写 `VITE_API_BASE=https://api.你的域名`。
2. **明文 HTTP**：Android 9+ 默认禁明文流量，用 `http://IP:8088` 要在 `AndroidManifest.xml` 加 `android:usesCleartextTraffic="true"`，正式环境请上 HTTPS。
3. **签名**：`npx cap open android` 后 `Build > Generate Signed Bundle/APK`，需要 keystore（自己生成并保管，丢了不能覆盖升级）。
4. **无本地 SDK 时**：可用 DCloud/应用宝等第三方云打包，或直接把 H5 传给 Android 同学帮出包。

## 以后要回小程序

不需要重写后端，也不需要重写 `web/` 之外的任何东西：

- 复用 `server/` 全部接口（同一套 `/v1/*` + Bearer Token）；
- 用 uni-app 或原生小程序重做 UI，`miniapp/` 里的 12 页可作为交互参考与字段对照；
- 小程序与 H5 可以共存：域名备案后，H5 走网页、小程序走 wx.request，数据天然一致。

## 对答辩口径的影响

PPT 里写的是小程序，答辩时建议这样表述（诚实且站得住）：

> "考虑到小程序需要 AppID、真机预览与审核，验证周期长，我把用户端做成了**响应式 Web（H5）**，一套代码同时适配手机与 PC，可随时用 Capacitor 封装为 Android APK；小程序端已完成参考实现（`miniapp/`，12 页），与 Web 共用同一套 REST 接口。这样把有限的时间投入到了**担保交易、动态核销码、接龙聚合**这些真正的业务难点上。"
